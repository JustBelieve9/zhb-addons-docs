# zhb: руководство по аддонам

Редакция 29.10.2026. Blender 5.2 LTS.

| Аддон | Версия | Назначение |
|---|---|---|
| zhb Stax | 0.1.0 | Стопки, перелёты, сортировка и сбор |
| zhb Leafs | 0.1.0 | Листва, пыль, камешки и обломки |
| Zondbe | 0.25.3 | Толпа; переработка отложена |
| PhysX | 0.56.0 | Физика Box3D; UI без Expert Mode |
| Studio | 0.35.0 | Подготовка, оптимизация, варианты и сбор проекта |
| Core | 0.8.2 | Проверки кэша в скиллах Blender |

Stax и Leafs заменяют Animation. Перед включением новых пакетов отключите
Animation и старый отдельный Particle Effects. Сохранённые RNA-имена стопок
и частиц сохранены. Camera Rig исключён из аддонов; его сценарий доступен в zhb-blender. Существующие объекты камеры не удаляются.

Stax, Leafs, Zondbe, PhysX и Studio автономны. Core нужен скриптам Collect, проверки рендера и Scene Doctor из zhb-blender.
Studio остаётся доступным. BlAe выведен из состава и архивирован по решению пользователя. Карта действий и звуков для AE формируется через sound_cues.py в zhb-blender; покадровый трекинг и JSX-импорт BlAe больше не входят в рабочий процесс.

## Установка

Установите ZIP через Preferences → Add-ons → Install from Disk и включите
нужный аддон. После обновления перезапустите Blender.

## Репозитории и релизы

- [Stax](https://github.com/JustBelieve9/zhb_stax/releases/latest) и [Leafs](https://github.com/JustBelieve9/zhb_leafs/releases/latest).
- [PhysX](https://github.com/JustBelieve9/zhb_physx_solver/releases/latest): выбирайте архив своей платформы.
- [Zondbe](https://github.com/JustBelieve9/zhb_zondbe/releases/latest), [Studio](https://github.com/JustBelieve9/zhb_studio/releases/latest).
- [Core](https://github.com/JustBelieve9/zhb_core/releases/latest), [скиллы Blender](https://github.com/JustBelieve9/zhb-blender-skills).

Studio открыт; остальные репозитории аддонов приватны и требуют доступа к GitHub.

## Интерфейс PhysX

В N → zhb PhysX доступны Объекты, Разрушение, Симуляция, Результат и
Конвертация Bullet ↔ Box3D. Параметры объектов — в Properties → Physics.
Expert Mode убран; дополнительные параметры раскрываются по смыслу.
## 4. Порядок работы

Девять сценариев. В каждом — по шагам, и что должно получиться.

### 4.1. Новый файл под мобильный креатив

1. **zhb Studio → Проект → Подготовка проекта**. Нажмите
   **Подготовить проект**. Ставит разрешение, FPS,
   цветоуправление и композитор под вертикальный креатив.
   *Результат:* файл настроен под мастер-формат, из которого потом режутся 9:16,
   4:5 и 16:9.
2. **Проект → Направляющие кадра**. Включите рамки. Во вьюпорте появятся границы
   форматов поверх камеры.
   *Результат:* видно, что не вылезет за кадр ни в одном из форматов.
3. **Проект → Автосохранение**. Включите снимки, если работа длинная.
   *Результат:* копии файла рядом с проектом, ротация по возрасту.
### 4.3. Стопка, перелёты и сортировка по корзинам

1. **zhb Stax**. Задайте источник: **Объект** или
   **Коллекция** (во втором случае каждый элемент — случайный объект из неё,
   выбор управляется Seed).
2. Размеры сетки: Columns / Depth / Levels, зазоры, масштаб. **Создать стопку**.
   *Результат:* стопка linked-дубликатов под контроллером-пустышкой.
3. При выбранном контроллере редактируется существующая стопка. Размеры,
   источник и интервалы применяются кнопкой **Перестроить стопку**.
   Анимация количества: ключи свойства **Количество** на контроллере. Элементы
   появляются и исчезают по этому числу, с отскоком. После установки ключей
   нажмите **Запечь анимацию**. Сворачивание дополнительных блоков их
   настроек не меняет; активные возможности помечены в заголовках.
4. Раскройте **Перелёты**: задайте цель или коллекцию целей, максимум
   элементов и длительность. На контроллере задайте ключи свойства
   **Перелёт**, затем нажмите **Запечь анимацию**.
   *Результат:* элементы по одному улетают к цели по дуге.
5. **Сортировка по корзинам.** Раскройте **Сортировка**, выберите **By Kind**. На исходном объекте
   поставьте пользовательское свойство `zhb_kind` (имя настраивается), такое же
   — на объекте-корзине со значением, которое она принимает.
   *Результат:* каждый предмет летит в свою корзину. Предмет, которому корзины
   нет, **остаётся в стопке** и попадает в отчёт — в чужую его не досыпают.
6. **Сбор пустышкой.** Раскройте **Автоматический сбор**: укажите персонажа и коллекцию
   триггеров, радиус и сколько предметов даёт одно срабатывание. Нажмите
   **Рассчитать автоматический сбор**.
   *Результат:* проводите персонажа по сцене — каждая точка срабатывает один раз,
   стопки копятся.
7. В блоке **События сбора** галочка **Записывать события** пишет прилёты в текстовый блок
   **«zhb Collect Events»**: кадр, корзина, предмет, вид, накопленный итог.
   *Результат:* готовый вход для счётчика в After Effects (см. 4.7).

### 4.4. Толпа

1. **Разметьте сцену.** «Проверить роли сцены» показывает наличие земли,
   источников и целей, не меняя объектов. После смены ролей или состава
   проверку нужно повторить. Вкладка физики объекта или **zhb Anim → Толпа → 1. Подготовка сцены**:
   - **Ground** — ровный меш, по его габаритам строится сетка. Должен быть ровно один.
   - **Obstacle** — непроходимое.
   - **Zone** — цель. Радиус равен размеру пустышки; стрелка вместо сферы
     означает направление, а не место.
   - **Spawn** — откуда появляются. Пустышка даёт диск, любой другой объект —
     эмиттер по рёбрам.
   - **Gate** — ворота, меняющие численность (см. ниже).
2. В **2. Персонажи** задайте пары Idle/Run и постройте инстансинг.
   Изменили список — перестройте его. В **3. Движение** настройте скорость,
   плотность и качество; выбор пресета требует отдельного применения.
   **Толпа → 4. Расчёт и результат → Рассчитать толпу.**
   *Результат:* точечное облако `ZondbeCrowdPoints` с атрибутами (позиция,
   направление, скорость, фаза, состояние, команда, `alive`). На него вешаются
   геоноды с персонажами.
3. **Толпа → Расчёт и результат → Хранение и очистка кэша** — где живёт бейк: внутри `.blend` или файлом рядом. Там же в **Дополнительных настройках**
   **Прогрев, кадров**: сколько кадров досчитать *до* первого кадра сцены, чтобы
   толпа успела прибежать и устояться.
4. **Ворота.** Объект с ролью Gate, операция ×N / +N / −N.
   *Результат:* толпа, проходя через них, растёт или убывает. Каждое тело
   проходит одни ворота **один раз**.
   *Важно:* всё, что ворота смогут выпустить, выделяется **до** бейка. Потолок —
   **Gate Reserve Cap**; упёрлись в него — бейк скажет словами, на экране это
   выглядит просто как переставшая расти толпа.
5. **Бой.** Панель **Толпа → Бой**: включить, задать радиус контакта, урон и паузу
   между попаданиями. Команда и здоровье — на спавнере.
   *Результат:* агенты разных команд убывают при сближении; павший исчезает
   штатно, как ушедший за кадр. Команда доезжает до точек атрибутом
   `agent_team` — по нему геоноды красят стороны.
   *Важно:* пауза между попаданиями обязательна, иначе двое, идущие рядом,
   убивают друг друга на первом же кадре касания.
6. **Радиусы толпы простыми словами.** Их три, и каждый про своё:
   - **Радиус тела** — «сколько места занимает один человек»: половина обхвата
     персонажа. От него считается, когда двое столкнулись плечами.
   - **Радиус разделения** — «на каком расстоянии толпа держится, не толкаясь»:
     радиус тела плюс доля обхвата, умноженная на плотность. Чем плотнее
     назначена толпа, тем ближе люди стоят.
   - **Радиус взгляда** — «за сколько шагов человек видит, куда идёт»: растёт
     со скоростью, а не с размером — быстрый бегун смотрит дальше.
7. **Пресет вместо радиусов.** В блоке **3. Движение** выбор
   **Свободнее / Обычно / Плотнее** и характера движения заполняет все три
   радиуса и силу расталкивания согласованным набором; «Обычно» равно
   умолчаниям аддона.
   Кнопка **Measure Girth** оценивает обхват по габаритам прототипов — мерится
   самый широкий прототип, а не сумма расставленных объектов. Пределы
   автооценки: модификаторы на прототипе и пустой выбор отклоняют оценку
   с причиной; оценка — стартовое значение, финальную плотность всё равно
   крутит художник. Ручная правка после пресета честно читается
   «изменено вручную».

### 4.5. Физика

1. Выделите объекты, **zhb PhysX → 1. Объекты**: **Динамические** (двигаются решателем)
   или **Неподвижные** (стоят; с ключами — толкают динамические).
2. Форма столкновений — в Properties → Physics → **Box3D Body**. Бокс и сфера
   дёшевы; **Mesh только для неподвижного Passive**; для движущегося вогнутого
   тела — **Compound** из детей.
3. Включите **Show Collision Shapes**, чтобы увидеть во вьюпорте ту форму,
   которой объект реально сталкивается.
   *Результат:* сразу видно, что коллизия не того размера или не там.
4. **2. Симуляция** — качество, диапазон кадров, режим вывода и запуск;
   гравитация и подшаги — в **Параметры симуляции и диагностика**:
   - **Keyframes** — обычные ключи, редактируются в Graph Editor;
   - **Blend Cache** / **Disk Cache** — сырые кадры, проигрываются обработчиком;
   - **Instanced** — для тысяч тел: одно point-instance вместо тысячи объектов.
5. **Рассчитать физику**. Состояние рядом с запуском, проверка и
   преобразование — в **3. Результат**, Clear Cache / Clear All —
   в раскрываемом блоке **Очистка результата**.
   *Результат:* движение записано; сцена дальше просто проигрывает готовое.
6. **Пресет качества** в блоке **2. Симуляция**: **Черновик / Обычное / Точно** меняет
   только согласованную тройку решателя — подшаги, герц контактов,
   демпфирование; «Обычное» равно умолчаниям. Масса, гравитация и время пресету
   не принадлежат; ручная правка после пресета читается «изменено вручную».
7. Дополнительно: **Fracture** (разрушаемые стены), **Mark Joint** на пустышках
   (шарниры, верёвки), **Mark Trigger** (зона, включающая физику по проходу),
   **Mark Tool** (притянуть, унести, ударить импульсом).
8. **Конвертация Bullet ↔ Box3D** — если файл пришёл собранным под родную физику Blender:
   **Bullet To Box3D** переносит active/passive и формы столкновений.
   *Результат:* то, для чего честного соответствия нет (цилиндр, конус,
   меш-форма на движущемся теле), **не трогается**, выделяется и объясняется в
   текстовом блоке «Box3D Convert». Масса и трение не переносятся — ими владеет
   каждый движок сам.

### 4.6. Частицы по удару

1. Выделите Mesh-объект и выберите **zhb Leafs**. В блоке
   **1. Создание эффекта** задайте тип эффекта и, при необходимости, коллекцию.
2. Нажмите **Создать эффект**: существующий Prepare измеряет источник и
   создаёт процедурную систему одним действием. Повторное нажатие обновляет её.
   Отдельное измерение доступно в **Анализ источника**.
3. В **2. Запуск** выберите режим: кнопка **Запустить эффект**, ключ-галочка
   или сближение с пустышкой. Для сближения укажите цель; её отсутствие
   отображается предупреждением. Радиус — расстояние от габарита объекта.
4. В **3. Внешний вид** настройте количество, размер, скорость и время жизни.
   Смена типа эффекта сама не применяет значения по анализу: для этого есть
   отдельная кнопка. Fade виден в Basic у пыли и смешанного эффекта.
5. **Проверка процедурной системы** проверяет геоноды и синхронизацию.
   Это процедурный эффект без симуляционного кэша.

### 4.7. Отдача в After Effects

1. **zhb Studio → Передача → After Effects → Отдельный экспорт трекинга.** Выберите объекты и камеру,
   укажите файл, **Export Tracking**.
   *Результат:* JSON с экранными координатами по кадрам + JSX-импортёр, который
   собирает из него слои в AE.
2. **After Effects → События.** Кнопка **Add Mark** заводит метку, поля
   выделенной — в подпанели **Выбранное событие**: кадр, категория, шина, объект,
   заметка. Или **Поиск событий** — удары, появления, смена текста, склейки.
3. Если в сцене работала сортировка из 4.3, включите детектор **Collect**.
   *Результат:* каждый прилёт становится событием категории Counter с полями
   **Amount** и **Total** — числом, по которому в AE рисуется счётчик. Считает
   Blender, AE только показывает.
4. **Отдельный экспорт событий** — JSON со временем в секундах, экранными координатами,
   именами слоёв и FPS.
5. **Пакет для After Effects:** выберите сохранённый исходный `.blend` и первый файл
   готовой PNG/EXR-последовательности, затем **Собрать пакет для After Effects**.
   *Результат:* переносимая папка/ZIP с кадрами, tracking/events и AE-импортёром.
   Данные читаются из выбранного файла отдельным Blender. Целостность и размеры
   кадров проверяются; их соответствие исходному `.blend` указывает пользователь.
   Старые журналы доступны под отдельной галочкой.

### 4.8. Варианты и передача

1. **zhb Studio → Варианты:** создайте набор, настройте замены и проверьте предпросмотр. «Вернуться к базе» восстанавливает сцену.
2. Сохраните вариант или включённый набор в отдельные `.blend`; рендерите нужный файл средствами Blender.
3. Перед финалом верните оригинальные текстуры. Диагностика сцены и прокси доступны в «Оптимизация».
4. **Передача → Собрать проект** собирает переносимую копию с ресурсами.

## Дополнительные настройки и состояние результата

Раскрываемые блоки и переключатели «Дополнительные настройки» управляют
видимостью. Они не отключают скрытые функции, не применяют пресеты и не
пересчитывают результат. Состояние навигации хранится на WindowManager;
сохранённые параметры Scene/Object остаются данными сцены. Это не единый
глобальный режим: у толпы несколько независимых переключателей, у других
инструментов часть расширенных полей использует общий переключатель пакета.

Необычные скрытые значения могут показываться краткой сводкой, а активные
возможности — пометкой «включено». Для возврата значения используйте само
поле или явно применяемый пресет. Выбор пресета и применение — разные действия.
READY относится к проверенному результату; после внешней правки повторите
проверку актуальности. STALE требует пересчёта, а неполный результат нельзя
считать готовым только потому, что он проигрывается.

### Раскрытие настроек после UX-проверки

У толпы по умолчанию открыты подготовка и расчёт. После успешной проверки
роли сворачиваются в краткую сводку; изменить их можно в «Изменить роли объектов».
Персонажи и движение раскрываются отдельно. После изменения целей повторите
«Проверить роли сцены»: устаревшая проверка не подтверждает ни наличие, ни отсутствие целей.
В движении, обходе целей, хранении кэша и бое свои независимые дополнительные
настройки. Расширенные параметры роли объекта доступны в Properties → Physics.

У PhysX качество, диапазон, представление результата и «Рассчитать физику»
показываются перед блоком «Параметры симуляции и диагностика».
У частиц «Дополнительные настройки» находятся рядом с количеством, размером
и скоростью в панели внешнего вида, а не в настройках типа эффекта.
## 5. Справочник интерфейса

Ниже — панели зарегистрированных пакетов, включая скрытые текущим
выбором инструмента, и извлечённые из их отрисовки элементы: кнопки с их подсказками и поля с их описаниями и значениями по
умолчанию. Раздел собран из зарегистрированных классов, поэтому он полон по
построению: полнота операторов проверяется при сборке.

Как читать этот раздел вместе с разделом 4. Справочник перечисляет **все**
поля панели; выбор инструмента, раскрытие блоков и
**Дополнительные настройки** (раздел 4) определяют видимость — значения от режима
не зависят. Владельца данных определяет RNA-свойство, а не расположение панели:
частицы, например, доступны в сайдбаре, но хранятся в `Object.zhb_pe`.
Навигация и дополнительные настройки относятся к сеансу и не сохраняются
как параметры сцены. Что меняет кнопка Apply и что является пресетом, а что
ручной правкой, сказано в подсказках и в разделе 4. Что происходит со
дочерними процессами при обновлении кода — раздел 9
в конце.

Где у одного имени поля в аддоне несколько разных значений (например,

##### Анализ и оптимизация

*Где:* zhb Studio

Анализ и очистка неиспользуемых данных, объединение дубликатов изображений, материалов и мешей, упрощение дорогих шейдеров.

- **Analyse Scene** — Посчитать, из чего складывается стоимость сцены: объекты в view layer, общие меш-датаблоки, дубли изображений и материалов, разрешения текстур, кто использует displacement и bump. Только читает и пишет отчёт -- файл не меняется; чистка сирот живёт отдельной кнопкой Purge Unused
- **Purge Unused** — Штатно почистить сцену: удалить датаблоки, на которые никто не ссылается. Текстовые блоки не трогаются никогда -- там скрипты и заметки. Меняет рабочий файл, Ctrl+Z отменяет. Analyse Scene этого не делает намеренно -- он только считает, и в отчёте может быть то, что удалит эта кнопка

Запускать ПОСЛЕ склейки изображений: пока одинаковые материалы ссылаются на разные датаблоки одной картинки, их отпечатки не совпадут

Объекты остаются на местах; меняется только то, на какие данные они ссылаются. Побочный эффект важнее прямого: появляется право на инстансинг
- **Strip Expensive Shader Nodes** — Убрать настоящий displacement и узлы Bump. Normal Map НЕ трогается -- он стоит копейки, а без него картинка становится плоской без выигрыша. Если в Bump заходил Normal Map, он переподключается напрямую
- **Principled -> Diffuse** — Заменить Principled BSDF на Diffuse BSDF: тот же Base Color (текстура или сплошной цвет) на входе Color, Roughness = 1.0, в Normal ничего не подключается, даже если оно было у Principled. Узлы внутри общих групп не трогаются, только считаются

#### Разрушение

*Где:* zhb PhysX · свёрнута по умолчанию

Генерация фрагментов выбранного объекта, настройка прочности и очистка результата.

- `Unbreakable` — Связи не рвутся ни при какой нагрузке, что бы ни стояло в Strength. Без этой галочки Strength 0 означает НУЛЕВУЮ прочность, то есть объект разваливается от любого касания -- это важно, когда Strength анимируется ключами: доводя её до нуля, вы разрушаете объект, а не делаете его несокрушимым *(по умолчанию False)*
- `strength` — несколько полей с этим именем в аддоне: Strength
- **Select Source** — Сделать активным исходный объект, из которого нарезаны эти осколки
- **Clear Fragments** — Удалить осколки этого объекта и вернуть оригинал
- `Cells` — Сколько осколков сгенерировать. Зёрна раскидываются равномерно по габаритному ящику объекта, поэтому у вогнутого источника часть зёрен попадает мимо меша и такие ячейки выбрасываются -- это верхняя граница, а не точное число *(по умолчанию 20)*
- `Seed` — Зерно генератора случайных чисел. Одно и то же значение даёт ровно те же осколки *(по умолчанию 0)*
- `linear_hertz` — несколько полей с этим именем в аддоне: Linear Stiffness (Hz)
- `angular_hertz` — несколько полей с этим именем в аддоне: Angular Stiffness (Hz)
- `linear_damping_ratio` — несколько полей с этим именем в аддоне: Linear Damping
- `angular_damping_ratio` — несколько полей с этим именем в аддоне: Angular Damping
- `Fragment Mass` — Задать массу каждому осколку напрямую вместо доли от массы источника. Без этого масса источника делится между осколками по объёму, и мелкие куски получаются очень лёгкими *(по умолчанию False)*
- `Mass` — Масса одного осколка, кг. Одинаковая у всех, независимо от размера. Меньше 0.01 кг не бывает: слишком лёгкое тело отлетает от первого же касания и выглядит как взрыв *(по умолчанию 1.0)*
- `Inner Material` — Материал для граней разлома. Без него скол рендерится наружным материалом, растянутым по срезу. Задаётся до генерации: слот дописывается в осколки, а гранях разлома заодно раскладывается плоская UV-развёртка по плоскости разреза
- **Generate Fragments** — Разбить выбранный меш на выпуклые осколки Вороного и записать граф связей между ними. Оригинал прячется, но остаётся в файле

#### Симуляция

*Где:* zhb PhysX

Качество, диапазон, представление результата и запуск расчёта. Гравитация, шаги решателя, прогрев и другие технические поля находятся в блоке «Параметры симуляции и диагностика».

- **Применить качество** — Записать в решатель подшаги и жёсткость контактов выбранного уровня. Только эти три поля; масса, гравитация и время не трогаются; при отказе ничего не меняется
- `Custom Frame Range` — Симулировать конкретный диапазон кадров вместо диапазона воспроизведения сцены (Start/End на таймлайне). Полезно, чтобы забейкать только часть длинной анимации, или диапазон за пределами текущего диапазона воспроизведения *(по умолчанию False)*
- `Start` — Первый кадр для симуляции, используется только когда включён Custom Frame Range *(по умолчанию 1)*
- `End` — Последний кадр для симуляции, используется только когда включён Custom Frame Range *(по умолчанию 250)*
- `Output` — Куда следующий бейк запишет результат. Ключевые кадры редактируемы, но раздувают .blend при больших количествах объектов/кадров. Blend Cache и Disk Cache пропускают f-кривые целиком и воспроизводятся вживую через frame-change хендлер. Instanced -- для тысяч тел: группирует объекты по общему мешу, прячет их и гоняет один инстансинг-объект на Geometry Nodes через bulk-запись атрибутов
    - **Keyframes** — Бейк в f-кривые. Редактируется в Graph Editor
    - **Blend Cache** — Хранит сырые данные симуляции внутри .blend файла, без ключевых кадров
    - **Disk Cache** — Хранит сырые данные симуляции в файлах рядом с .blend, без ключевых кадров
    - **Instanced** — Для тысяч тел: группирует помеченные объекты по общим данным меша, прячет оригиналы и гоняет один инстансинг-объект на Geometry Nodes через bulk-запись атрибутов вместо записи трансформа каждого объекта на каждый кадр
- **Toggle Originals In View Layer** — Убрать исходные объекты из view layer (или вернуть обратно). После Instanced-бейка результат несёт облако точек, а исходники нужны только как источник формы и параметров -- но каждый из них всё равно стоит вычисления depsgraph на каждом кадре. Измерено: 7.66 -> 0.47 мс/кадр на 3000 тел. Полностью обратимо: объекты возвращаются ровно в те коллекции, из которых были взяты
- **Рассчитать физику** — Симулировать помеченные объекты через Box3D и записать результат в выбранный вывод
- `Simulate On Playback` — Считать физику прямо во время воспроизведения таймлайна и кешировать её по ходу, как делает родная физика Blender. Симуляция стартует только с первого кадра диапазона (из середины продолжить нельзя -- в кеше лежат позиции, а не скорости); пауза сохраняет мир, так что повторное нажатие Play продолжает с места остановки. Результат явного бейка не перезаписывается -- сначала Clear zhb physx *(по умолчанию True)*
- `Live Preview` — Показывать симуляцию в вьюпорте и на таймлайне по мере бейка вместо ожидания готового результата. Считает физику пачками между перерисовками, максимально быстро, а не в реальном времени воспроизведения *(по умолчанию False)*
- `Workers` — Потоки солвера Box3D. Box3D работает лучше всего, если закреплён за performance-ядрами; efficiency-ядра и hyperthreading дают мало пользы, а иногда даже вредят. По умолчанию -- половина логических ядер, что близко к измеренному оптимуму и никогда не перегружает машину. Жёсткий потолок B3_MAX_WORKERS=32 *(по умолчанию 8)*
- `Sub-Steps` — Подшаги солвера на каждый симулируемый кадр. Box3D использует sub-stepping солвер: увеличение этого значения повышает точность контактов и суставов (меньше джиттера, меньше проникновения, жёстче суставы, лучше поведение быстрых объектов) примерно с линейной ценой за кадр. Собственное значение по умолчанию у Box3D -- 4 *(по умолчанию 4)*
- `Contact Hertz` — Жёсткость контакта, в циклах в секунду. Увеличение ускоряет, как быстро перекрывающиеся формы расталкиваются после быстрого столкновения, ценой более энергичного (дёрганого) расталкивания. Значение Box3D по умолчанию -- 30 *(по умолчанию 30.0)*
- `Contact Damping Ratio` — Упругость контакта, безразмерная величина. Уменьшение также ускоряет восстановление после перекрытия, ценой более энергичного расталкивания -- тот же компромисс, что и у жёсткости контакта. Значение Box3D по умолчанию -- 10 *(по умолчанию 10.0)*
- `Time Scale` — Ускоряет или замедляет симуляцию, как Time Scale в нативном Rigid Body World Blender'а -- 1.0 это обычное реальное время, выше -- всё происходит быстрее (за то же число забейканных кадров проходит больше симулированного времени), ниже -- медленнее *(по умолчанию 1.0)*
- `Warm-up Frames` — Сколько кадров просимулировать ДО первого кадра сцены, не записывая их. Ролик начинается с уже улёгшейся физики: засыпка успела осесть, стопка -- устояться. Отрицательных кадров в Blender нет (frame_start и frame_current зажимаются в ноль), поэтому это время существует только внутри солвера. Расписание при этом сохраняется: то, что назначено на первый кадр сцены -- например заполнение объёма эмиттером, -- случается в начале разогрева и успевает улечься, а назначенное на 30-й кадр по-прежнему происходит на 30-м. Стоит ровно столько же, сколько столько же обычных кадров *(по умолчанию 0)*
- `Stop When Settled` — Перестать считать физику, как только сцена полностью успокоилась, и просто дописать оставшиеся кадры последним положением. Кеш и кейфреймы получаются той же длины, что и обычно, -- экономится только время бейка. Включается лишь для сцен из одних динамических тел: эмиттеры, триггеры, инструменты и анимированные объекты умеют сдвинуть то, что уже улеглось, поэтому с ними проверка не запускается *(по умолчанию False)*
- `Kinematic After Bake` — Если у забейканного объекта есть нативный компонент rigid_body Blender'а, пометить его кинематическим, чтобы Bullet перестал симулировать его при воспроизведении. Без этого Bullet и забейканные данные будут одновременно управлять трансформом каждый кадр и конфликтовать друг с другом. Не влияет на объекты, использующие только маркировку Box3D *(по умолчанию True)*
- `Sample Rigs Through Depsgraph` — Считывать движение Passive/Trigger-объектов, чью анимацию нельзя прочитать напрямую с f-кривых (констрейнты, драйверы, NLA, парент к кости или вершине), спрашивая сам Blender по кадрам перед бейком. Без этого такой объект замирает там, где стоял, и ни на что не влияет -- ковш, прицепленный к костям риг-экскаватора, просто не толкает камни. Стоит одного пересчёта depsgraph на кадр, один раз перед бейком, и только для тех объектов, которым это реально нужно *(по умолчанию True)*
- `Force Fields` — Учитывать при бейке силовые поля Blender (Add > Force Field). Поддержаны типы Force и Wind: аддон читает настройки поля и сам считает силу по формулам Blender -- нативный движок физики Blender'а свои поля наружу не отдаёт. Поля действуют на Active-тела и частицы эмиттеров *(по умолчанию True)*
- `Effectors` — Учитывать только силовые поля из этой коллекции. Пусто -- брать все поля сцены (аналог Effector Collection в нативной физике)
- `Contact Points` — Записывать точки ударов в отдельный объект-облако: на каждый кадр -- где ударилось, по какой нормали и с какой скоростью сближения. Своих нод у него нет намеренно: искры, пыль или маркеры звука каждый собирает в геонодах сам, а аддон отдаёт данные. Атрибуты точки: normal_b3 (вектор), speed (м/с) и alive -- читайте alive, иначе получите и неиспользованные точки *(по умолчанию False)*
- `Min Speed` — Скорость сближения в м/с, ниже которой удар не записывается. Ноль здесь означает не "записывать всё", а "записывать в том числе то, как улёгшаяся куча шевелится на месте": такие касания забьют лимит кадра и вытеснят настоящие удары *(по умолчанию 2.0)*
- `Max Per Frame` — Сколько точек в облаке. Размер фиксирован, потому что меш не умеет уменьшаться при перемотке назад: каждый кадр пишет столько же точек, а alive говорит, какие из них настоящие. Удары сверх лимита теряются -- и об этом скажут после бейка *(по умолчанию 256)*
- `Show Collision Shapes` — Рисовать во вьюпорте сеткой ту форму, которой объект реально сталкивается -- не его меш, а бокс/сферу/капсулу/оболочку/компаунд, которые получит Box3D. Единственный способ увидеть, что коллизия стоит не там и не того размера, до бейка *(по умолчанию False)*
- `Selected Only` — Показывать форму столкновений только у выделенных объектов *(по умолчанию True)*
- `Profile Bodies` — Собирать во время бейка, во что обходится каждое тело: сколько у него контактов и сколько времени оно не спит. По итогам бейка выводит список самых дорогих объектов -- с них и надо начинать оптимизацию (упростить форму, включить сон, убрать триггером). Стоит один вызов на тело раз в Sample Every кадров *(по умолчанию False)*
- `Sample Every` — Как часто снимать замеры профайлера, в кадрах. Чем реже, тем меньше сам профайлер влияет на измеряемое время. 1 -- каждый кадр *(по умолчанию 5)*

##### Собрать проект

*Где:* zhb Studio

Поиск потерянных ресурсов и сбор независимой копии проекта по номеру задачи с текстурами, связанными файлами и проверкой путей.

- **Collect Project** — Собрать проект в отдельную папку: распаковать текстуры, скопировать алембики и прочие внешние файлы, переписать пути, вычистить неиспользуемое, сбросить путь вывода. Рабочий файл не изменяется

#### Результат

*Где:* zhb PhysX

Состояние и проверка рассчитанной симуляции, преобразование результата в ключи или объекты и отдельный блок очистки. Запуск расчёта находится в панели симуляции.

- **Проверить результат физики** — Пересчитать сигнатуру входов и проверить полноту результата Box3D. Тяжёлая проверка запускается только этой кнопкой и из Preflight
- **Cache To Keyframes** — Превратить уже забейканный кеш в обычные ключевые кадры, не пересчитывая симуляцию: Blend Cache и Disk Cache пишутся в f-кривые объектов, Instanced -- в f-кривые оригиналов, которые возвращаются из парковки, а облако точек и библиотека форм удаляются. Результат неотличим от бейка сразу в Keyframes, включая то, что потом вернёт Clear Cache
- **Instances To Objects** — Материализовать инстансы текущего кадра: по реальному объекту на каждый живой инстанс, с его мировой трансформацией и мешем из библиотеки форм (связанные дубликаты, не копии). Анимации в этих объектах нет намеренно -- облако точек хранит позы по кадрам без привязки к объектам, за анимированные объекты отвечает Cache To Keyframes. Аддон их дальше не отслеживает, Clear их не удаляет
- **Clear Cache** — Удалить только результат бейка: ключи анимации, кеши и облака точек. Осколки, их скрытые источники и пометки тел остаются на месте -- это кнопка для "перебейкать с другой прочностью". Полный сброс -- Clear zhb physx
- **Clear zhb physx** — Удалить забейканный вывод у помеченных активных объектов и вернуть сцену: осколки удаляются, их источники возвращаются, тела с родным rigid_body отдаются обратно Bullet. Только результат бейка снимает Clear Cache

#### Конвертация Bullet ↔ Box3D

*Где:* zhb PhysX · свёрнута по умолчанию

Перенос типов тел и форм коллизии между штатным Bullet и Box3D. Масса и трение остаются настройками соответствующего движка.

- **Bullet To Box3D** — Перевести объекты с нативной физики Blender на Box3D: Active и Passive тела и их формы столкновений. Переносится только выбор художника -- какие объекты тела, какого типа и какой формы. Масса, трение и упругость НЕ переносятся: ими владеет Box3D, и его значения согласованы между собой. Объекты, для которых честного соответствия нет (цилиндр, конус, меш-форма на движущемся теле), не трогаются, выделяются и перечисляются в тексте «Box3D Convert». Работает по текущему слою видимости
- **Box3D To Bullet** — Перевести помеченные для Box3D объекты обратно на нативную физику Blender: Active и Passive тела и их формы столкновений. Эмиттеры, триггеры, инструменты и соединения Box3D аналога у Bullet не имеют -- они не трогаются, выделяются и перечисляются в тексте «Box3D Convert». Работает по текущему слою видимости

##### 1. Подготовка сцены

##### 2. Персонажи

*Где:* zhb Anim · свёрнута по умолчанию

Выбор прототипов персонажей и пар Idle/Run, построение инстансинга персонажей на точках симуляции и его удаление.

- *список* — строки с галочкой включения
- **Add Character** — Добавить пару коллекций одного персонажа
- **Remove Character** — Удалить выбранную пару Idle / Run
- **Find Idle / Run Pairs** — Найти коллекции с одинаковым именем и суффиксами Idle / Run
- **Построить инстансинг** — Создать управляемый инстансинг пар Idle / Run
- **Remove Character Instancing** — Убрать с точек созданный аддоном инстансинг
- `Metres Per Cycle` — Сколько метров проходит персонаж за один цикл клипа ходьбы. Именно это прибивает стопы к земле, и вывести это неоткуда — снять с самого клипа *(по умолчанию 1.600000023841858)*

<!-- zhb-panel-anchor: solver-5-806 -->

##### 3. Движение

*Где:* zhb Anim · свёрнута по умолчанию

Скорость, художественные пресеты, радиусы, обход препятствий и ориентация толпы. Локальный переключатель «Дополнительные настройки» раскрывает параметры решателя.

- `Radius Overlay` — Показать радиусы толпы в мировых единицах wireframe-оверлеем: зум и вид ничего не искажают, размер диска равен настроенному
    - **Off** — Не рисовать ничего
    - **Collision** — Диск радиуса Agent Radius вокруг каждого агента — ровно то, чем агент сталкивается со стенами и друг с другом
    - **Separation** — Кольцо радиуса Separation Radius — внутри него агенты расталкиваются
    - **Both** — И диск, и кольцо
- `Speed` — Предпочитаемая скорость ходьбы, метров в секунду *(по умолчанию 1.399999976158142)*
- `Character Rotation` — Поправка к атрибуту rotation, если модель смотрит не вдоль локальной оси +Y *(по умолчанию 0.0)*
- `Cell Size` — Разрешение сетки. Препятствие тоньше клетки для поля не существует. Клетка помельче стоит времени бейка, а не времени кадра *(по умолчанию 0.25)*
- `Agent Radius` — Полуширина человека. На столько раздуваются препятствия, чтобы агента можно было считать точкой и он всё равно не влезал в стену плечом *(по умолчанию 0.30000001192092896)*
- `Wall Clearance` — Насколько близко разрешено пройти, сверх радиуса агента. Это жёсткий предел, а не пожелание: ближе не подойдёт никто и никогда. «Обход стен» рядом отвечает на другой вопрос — за сколько метров путь НАЧИНАЕТ отворачивать. Осторожно: зазор съедает узкие проходы, а округляется он вверх до целой клетки — фактическое число аддон печатает в отчёте бейка *(по умолчанию 0.0)*
- `Separation Radius` — В этом радиусе агенты расталкивают друг друга *(по умолчанию 0.699999988079071)*
- `Separation Force` — Насколько сильно. Слишком много — толпа кипит и разлетается, слишком мало — люди проходят друг сквозь друга *(по умолчанию 2.0)*
- `Look Ahead` — Максимальное ускорение, которое агент тратит на то, чтобы разойтись ЗАРАНЕЕ. Расталкивание рядом ждёт, пока столкновение уже произошло; предвидение считает, когда и где двое окажутся ближе всего, и уводит в сторону, пока место ещё есть. Именно из этого во встречном потоке сами собой складываются полосы. Ноль выключает. Замер на встречной толпе 120 человек: расслоение потоков 0.03 → 0.63 м, глубоких перекрытий втрое меньше, переход дольше примерно на 17% *(по умолчанию 4.0)*
- `Look Ahead Horizon` — На сколько секунд вперёд смотреть. Столкновение дальше этого срока не волнует никого. Больше — толпа начинает уворачиваться от людей, с которыми ещё десять раз разминётся *(по умолчанию 2.0)*
- `Look Ahead Radius` — В каком радиусе вообще искать, с кем расходиться. Должен быть заметно больше радиуса расталкивания, иначе смотреть вперёд не на кого. Прямо влияет на время бейка: пар для перебора растёт как квадрат радиуса *(по умолчанию 2.5)*
- `Speed Spread` — Разброс вокруг предпочитаемой скорости, свой у каждого агента. Ноль заставляет толпу двигаться как один механизм *(по умолчанию 0.15000000596046448)*
- `Acceleration` — Как быстро агент меняет скорость. Низкое читается как люди, высокое — как насекомые *(по умолчанию 6.0)*
- `Turn Rate` — Максимальный разворот направления движения за секунду. Меньше — плавнее дуги, но шире радиус поворота *(по умолчанию 6.2831854820251465)*
- `Wall Avoidance` — За сколько метров до стены путь начинает от неё отворачивать. Ноль — кратчайший путь, а он вплотную притирается к каждому углу: агенты идут прямо в препятствие и сворачивают, только упёршись *(по умолчанию 1.2000000476837158)*
- `Avoidance Force` — Во сколько раз дороже идти вплотную к стене. Больше — шире дуга обхода. Слишком много — толпа перестаёт пользоваться узкими проходами и пойдёт вокруг *(по умолчанию 3.0)*
- `Wall Sliding` — На таком расстоянии от стены из намерения агента убирается составляющая «в стену», и он идёт вдоль. Ноль выключает: агент будет упираться и дёргаться у поверхности *(по умолчанию 0.6000000238418579)*
- `Wall Escape Force` — Насколько сильно выталкивает того, кто уже внутри препятствия. Правильность держится не на этом, а на жёсткой постановке обратно наружу после шага; сила лишь делает выход плавным. Большие значения дают рывок *(по умолчанию 1.0)*
- `arrive_min` — несколько полей с этим именем в аддоне: Arrive From, Stop Short From
- `arrive_max` — несколько полей с этим именем в аддоне: Arrive To, Stop Short To
- `idle_min` — несколько полей с этим именем в аддоне: Idle From, Stay From
- `idle_max` — несколько полей с этим именем в аддоне: Idle To, Stay To
- `Standing Separation` — Во сколько раз слабее расталкиваются те, кто уже пришёл и стоит. Единица — пришедшая толпа никогда не успокаивается: расталкивание само по себе не имеет состояния покоя и медленно расползается наружу *(по умолчанию 0.25)*
- `Standing Room` — Какую долю радиуса расталкивания надо освободить, прежде чем пришедший агент имеет право встать намертво. Пока тесно, он расталкивается в полную силу и трение к нему не применяется — иначе толпа, пришедшая разом, замерзает друг в друге плотным комком с ровным круглым краем, и разброс дистанции прихода на вид перестаёт работать. Ноль — вернуть это поведение *(по умолчанию 0.6000000238418579)*
- `Standing Friction` — Сцепление стоящего с землёй, м/с². Единственное, что даёт толпе состояние покоя: расталкивание слабее этого гасится полностью и агент не двигается вообще, сильнее — он всё-таки подвинется. То есть это порог между «толпа устоялась» и «его правда толкают». Ноль — вернуть бесконечное расползание *(по умолчанию 1.5)*
- `Standing Speed` — Потолок скорости для стоящих, метров в секунду. Страховка поверх трения: ограничивает, но сам по себе не останавливает *(по умолчанию 0.15000000596046448)*
- `Substeps` — Шагов солвера на кадр. Поднимать только если плотная толпа взрывается: подшаги меняют результат, а не уточняют его *(по умолчанию 1)*
- `Debug Step` — Рисовать каждую N-ю клетку поля. Вся сетка разом нечитаема и долго строится *(по умолчанию 4)*

<!-- zhb-panel-anchor: goals-5-795 -->

###### Цели и порядок обхода

*Где:* zhb Anim · свёрнута по умолчанию

Выбор целей движения агентов, зон назначения и поведения очереди, включая удержание и выпуск по триггеру.

- `Zone Order` — Как толпа выбирает следующую зону
    - **Random** — Из зоны в любую другую, бесконечно. Живая улица: конца у этого нет по замыслу
    - **In Order** — Маршрут: зона за зоной по их полю «Порядок», и на последней толпа остаётся. Последняя зона — настоящий финал кадра, а не очередная остановка
    - **Random, Then Exit** — Несколько случайных зон, потом последняя по полю «Порядок» — она и есть выход. Для сцены, где толпа разбредается по стойкам и уходит: в «Случайно» выход — такая же зона, как все, поэтому часть агентов уходит сразу, а часть не уходит никогда
- `Min Zones` — Сколько зон агент обойдёт, прежде чем пойти на выход. Считается вместе с той, в которой он появился *(по умолчанию 2)*
- `Max Zones` — Верх того же разброса. Одно число на всех значит, что толпа развернётся к выходу разом — разброс размазывает уход по времени *(по умолчанию 4)*
- **Проверить роли сцены** — Проверить наличие земли, источников и целей. Объекты и роли не меняются

<!-- zhb-panel-anchor: battle-5-843 -->

##### Бой

*Где:* zhb Anim · свёрнута по умолчанию

Настройка боевого поведения агентов и взаимодействия команд во время симуляции толпы.

- `Crowd Against Crowd` — Агенты разных команд бьют друг друга при сближении. Выключено — не стоит ничего: поиск пар не запускается вовсе. Команда задаётся на спавнере *(по умолчанию False)*
- `Contact Radius` — На каком расстоянии агенты разных команд считаются сошедшимися. Столкновений в этом солвере нет — «контакт» это перекрытие двух радиусов *(по умолчанию 0.800000011920929)*
- `Damage Per Hit` — Сколько единиц здоровья снимает одно попадание *(по умолчанию 1.0)*
- `Hit Every` — Сколько кадров проходит между двумя попаданиями по одному агенту. Без паузы двое, идущие рядом три секунды, убивают друг друга на первом же кадре касания *(по умолчанию 6.0)*
- `Gate Reserve Cap` — Потолок числа агентов, заранее выделенных под ворота. Массив агентов не может расти по ходу симуляции — точечное облако с меняющимся числом вершин не переносит атрибуты между кадрами, — поэтому всё, что ворота смогут выпустить, выделяется заранее и ждёт с alive=0. Упёрлись в потолок — бейк скажет об этом *(по умолчанию 4000)*

##### 4. Расчёт и результат

*Где:* zhb Anim

Запекание движения толпы в выбранном диапазоне, прогрев и проверка результата. Повторное запекание требуется после изменения входов.

- `Seed` — Тот же сид — тот же бейк. Смена перетасовывает позиции спавна, скорости и длительность стоянок *(по умолчанию 0)*
- `Live Preview` — Показывать толпу прямо во время запекания. Бейк идёт модально в любом случае — этот флаг решает только, рисовать ли промежуточное. Выключенный считает заметно быстрее: кадры не переписываются в сцену и вьюпорт не перерисовывается *(по умолчанию True)*
- **Рассчитать толпу** — Просимулировать диапазон кадров сцены и записать каждый кадр
- **Проверить результат толпы** — Проверить, соответствует ли кэш текущей сцене и покрывает ли он весь диапазон

###### Хранение и очистка кэша

*Где:* zhb Anim · свёрнута по умолчанию

Загрузка, проверка и очистка кэша движения. Состояние кэша показывает, соответствует ли сохранённый результат текущей сцене и диапазону.

- `Warm-up Frames` — Сколько кадров просчитать до первого кадра сцены. Например, при старте сцены 1 и прогреве 120 кэш начнётся с -119: толпа успеет прибежать со спавнов и устояться в очередях к кадру 1 *(по умолчанию 0)*
- `Store Cache` — Где живёт запечённое между сессиями
    - **In The File** — В самом .blend, текстовым датаблоком. Кэш не потеряется при переносе проекта, но файл сцены растёт и сохраняется дольше
    - **On Disk** — Файлом .zondbe.npz рядом с .blend. Сцена остаётся лёгкой, но кэш легко забыть при переносе. Несохранённый файл кладёт его во временную папку
- **Load Cache** — Прочитать запечённое из файла или с диска
- **Clear Cache** — Убрать запечённое: и из файла, и с диска
- **Clear Bake** — Сбросить запечённое и снять обработчик кадра
- **Show Field** — Построить меш из отрезков — поле направлений к выбранной зоне

#### Частицы

*Где:* zhb Leafs

Процедурные частицы Geometry Nodes по удару: листва, пыль и обломки. Каждый кадр вычисляется от момента запуска без симуляционного кэша.


<!-- zhb-panel-anchor: setup-5-1018 -->

##### 1. Создание эффекта

*Где:* zhb Leafs

Измерение выбранных мешей или коллекции и создание системы частиц на каждом объекте. Учитываются размер, площадь и цвет материала.

- `Collection` — Если задана, «Подготовить» и «Анализировать» работают по всей коллекции, а не по выделению
- `Debris` — Набор значений по умолчанию и форма частиц. Смена эффекта сама по себе ничего не пересчитывает — для этого рядом есть кнопка «Значения по анализу»
    - **Leaves** — Листья сыплются и кружат: медленно, долго, с качанием
    - **Dust** — Мелкая пыль: много, легко, почти невесома
    - **Pebbles** — Щебень и камешки: тяжело, быстро падают
    - **Dust And Pebbles** — Одна система из двух видов частиц: пыль и щебень
- **Создать / обновить эффект** — Измерить выделение и поставить на каждый меш одну систему частиц. Повторный вызов обновляет уже готовые объекты, не добавляя вторую систему
- `Enabled` — Выключить, не удаляя: система остаётся на объекте со всеми настройками, но не считается и не рисуется *(по умолчанию True)*
- **Применить значения по анализу** — Пересчитать частицы, размер и скорости по последнему измерению для выбранного эффекта
- **Измерить источник** — Измерить выделенный меш или коллекцию и показать цифры, по которым считаются значения

<!-- zhb-panel-anchor: trigger-5-1040 -->

##### 2. Запуск

*Где:* zhb Leafs

Запуск частиц приближением пустышки, анимируемой галочкой или кнопкой. Настройка радиуса удара и момента срабатывания.

- `Trigger` — —
    - **Checkbox** — Галочка на объекте. Ставьте ключи — каждый переход «выкл → вкл» это удар
    - **Empty** — Объект-триггер: удар, когда пустышка подходит к габариту ближе радиуса
    - **Manual Only** — Ничего не отслеживается: удар ставится кнопкой «Удар сейчас»
- `Object` — Пустышка-триггер: топор, кулак, летящий камень. Годится любая пустышка, в том числе анимированная
- `Impact Radius` — На каком расстоянии от габарита объекта пустышка считается ударом. Внутри габарита расстояние ноль *(по умолчанию 0.5)*
- **Radius From Bounds** — Предложить радиус удара по габаритам: 12% наибольшей стороны. Ручное значение заменяется только этой кнопкой
- `Trigger` — Галочка-триггер. Щёлкните по ней правой кнопкой и поставьте ключи, или нажмите «Ключ на этом кадре» *(по умолчанию False)*
- **Key On This Frame** — Поставить галочку на текущем кадре и ключ «выключено» за кадр до него: получается один удар именно здесь
- **Запустить эффект** — Запустить систему на текущем кадре

<!-- zhb-panel-anchor: particles-5-1055 -->

##### 3. Внешний вид

*Где:* zhb Leafs

Количество, размер, скорость и разброс частиц, гравитация, сопротивление, вращение, покачивание, время жизни и уменьшение при исчезновении.

- `Count` — Сколько частиц выпускает один удар. Плотность считается по площади, поэтому у большого дерева листьев больше *(по умолчанию 200)*
- `Lifetime` — — *(по умолчанию 3.5999999046325684)*
- `Size` — Размер частицы относительно её собственной формы *(по умолчанию 0.11999999731779099)*
- `Size Spread` — — *(по умолчанию 0.5)*
- `Speed` — Начальная скорость разлёта, м/с *(по умолчанию 2.0)*
- `Speed Spread` — — *(по умолчанию 0.6000000238418579)*
- `Scatter` — Ноль — строго по нормалям поверхности, единица — во все стороны одинаково *(по умолчанию 0.6000000238418579)*
- `Upwards` — Насколько разлёт заваливается вверх: удар выбивает частицы вбок, а не в пол *(по умолчанию 0.4000000059604645)*
- `Gravity` — Листва падает медленно, щебень — быстро *(по умолчанию 9.8100004196167)*
- `Drag` — Торможение о воздух. Без него вся стая летит одним жёстким снопом *(по умолчанию 1.2000000476837158)*
- `Spin` — Оборотов в секунду: листья кувыркаются, камешки тумблятся *(по умолчанию 6.0)*
- `Sway` — Боковое покачивание в полёте — то, что отличает лист от камня *(по умолчанию 0.30000001192092896)*
- `Fade Out` — Какую долю жизни частица уменьшается до нуля. Ноль — исчезает рывком *(по умолчанию 0.3499999940395355)*
- `Colour` — Берётся из материала меша при подготовке. Материал частиц общий для всех объектов с таким же цветом *(по умолчанию 0.0)*
- `Pebble Share` — Сколько камешков в смешанном эффекте, остальное — пыль *(по умолчанию 0.3499999940395355)*
- **Apply To Selected** — Раздать настройки активного объекта остальным выделенным

#### Box3D Bake · запекание сцены

*Где:* Properties → physics · свёрнута по умолчанию

Управление запеканием физической сцены из редактора свойств; общие настройки решателя доступны во вкладке zhb PhysX.

- **Рассчитать физику** — Симулировать помеченные объекты через Box3D и записать результат в выбранный вывод
- `Simulate On Playback` — Считать физику прямо во время воспроизведения таймлайна и кешировать её по ходу, как делает родная физика Blender. Симуляция стартует только с первого кадра диапазона (из середины продолжить нельзя -- в кеше лежат позиции, а не скорости); пауза сохраняет мир, так что повторное нажатие Play продолжает с места остановки. Результат явного бейка не перезаписывается -- сначала Clear zhb physx *(по умолчанию True)*
- `Live Preview` — Показывать симуляцию в вьюпорте и на таймлайне по мере бейка вместо ожидания готового результата. Считает физику пачками между перерисовками, максимально быстро, а не в реальном времени воспроизведения *(по умолчанию False)*
- **Проверить результат физики** — Пересчитать сигнатуру входов и проверить полноту результата Box3D. Тяжёлая проверка запускается только этой кнопкой и из Preflight
- **Cache To Keyframes** — Превратить уже забейканный кеш в обычные ключевые кадры, не пересчитывая симуляцию: Blend Cache и Disk Cache пишутся в f-кривые объектов, Instanced -- в f-кривые оригиналов, которые возвращаются из парковки, а облако точек и библиотека форм удаляются. Результат неотличим от бейка сразу в Keyframes, включая то, что потом вернёт Clear Cache
- **Instances To Objects** — Материализовать инстансы текущего кадра: по реальному объекту на каждый живой инстанс, с его мировой трансформацией и мешем из библиотеки форм (связанные дубликаты, не копии). Анимации в этих объектах нет намеренно -- облако точек хранит позы по кадрам без привязки к объектам, за анимированные объекты отвечает Cache To Keyframes. Аддон их дальше не отслеживает, Clear их не удаляет
- **Clear Cache** — Удалить только результат бейка: ключи анимации, кеши и облака точек. Осколки, их скрытые источники и пометки тел остаются на месте -- это кнопка для "перебейкать с другой прочностью". Полный сброс -- Clear zhb physx
- **Clear zhb physx** — Удалить забейканный вывод у помеченных активных объектов и вернуть сцену: осколки удаляются, их источники возвращаются, тела с родным rigid_body отдаются обратно Bullet. Только результат бейка снимает Clear Cache

<!-- zhb-panel-anchor: box3d-body-4-1095 -->

#### Box3D Body · тело, эмиттер, триггер

*Где:* Properties → physics · свёрнута по умолчанию

Роль выбранного объекта, форма коллизии, масса, материал, ограничения движения, параметры эмиттера или триггера в симуляции Box3D.

- `Type` — —
    - **Active** — Динамическое тело, двигается солвером
    - **Passive** — Без анимации -- статичное тело, никогда не двигается. С анимацией (keyframes на самом объекте или родителе) -- кинематическое, толкает Active-тела своим движением
    - **Emitter** — Источник частиц: сам физическим телом не является, а испускает новые динамические частицы с поверхности своего меша по ходу бейка. Частицы всегда выводятся отдельным point-cloud объектом, независимо от выбранного Output
    - **Trigger** — Зона-сенсор: сам ни с чем не сталкивается, но объекты, попавшие в его объём, получают выбранное действие -- включить физику, заморозить или убрать. Может быть анимирован ключами, чтобы проехать по объектам и включить их на ходу
    - **Tool** — Инструмент: тянет тела к себе, уносит их в заданную точку или бьёт разовым импульсом. Как и триггер, сам ни с чем не сталкивается и может быть анимирован ключами -- см. Mode
- `Solver` — Что именно считает солвер для частиц этого эмиттера. Решение общее на всю сцену: облако точек и его кеш одни на все эмиттеры, поэтому Points включается только если на Points переведены ВСЕ эмиттеры сцены -- иначе бейк предупредит и посчитает всё как Rigid
    - **Rigid** — Полноценные тела: ориентация, тензор инерции, качение. Частица кувыркается при падении и ложится гранью. Кеш -- 7 float на частицу на кадр
    - **Points** — Только точки с радиусом: позиция, скорость, масса. Ни ориентации, ни вращения -- инстансы стоят без поворота. Кеш -- 3 float на частицу на кадр, то есть в 2.3 раза меньше. Для песка, гравия, брызг и всего, где кувыркание частицы не читается
- `Distribution` — Откуда эмиттер берёт точки рождения частиц
    - **Surface** — С поверхности меша, равномерно по площади: поток, струя, осыпь. Частицы идут по Rate за кадр в диапазоне Emit Start..Emit End
    - **Volume** — Заполнить ОБЪЁМ меша решёткой частиц и выпустить их все разом на кадре Emit Start -- бассейн с ресурсом, ящик с рудой, засыпанный контейнер. Меш должен быть замкнутым. Rate, Emit End и Normal Speed в этом режиме не участвуют
- `Spacing` — Шаг решётки заполнения, в метрах. Количество частиц не задаётся напрямую -- его определяет то, сколько ячеек влезло в объём. Решётка, а не случайные точки, потому что случайная засыпка рождает тела внахлёст, и движок расталкивает их на первом же шаге: вместо бассейна получается взрыв *(по умолчанию 0.25)*
- `Jitter` — Случайный сдвиг каждой частицы от узла решётки, долей СВОБОДНОГО ЗАЗОРА между соседями (шаг минус размер частицы), а не долей шага. Поэтому 1.0 -- всё ещё укладка без пересечений, а не рассыпанная каша. При шаге меньше размера частицы зазора нет и джиттер ничего не делает *(по умолчанию 0.0)*
- `Max Particles` — Потолок на количество частиц заполнения. Решётка обходится снизу вверх, так что при срабатывании потолка объём заполнен от дна -- как недолитый бассейн, а не срезанный по диагонали. Бейк сообщает, что упёрся *(по умолчанию 5000)*
- `Emit Start` — Первый кадр, на котором эмиттер испускает частицы *(по умолчанию 1)*
- `Rate` — Сколько частиц испускать за кадр. Дробные значения работают корректно: 2.5 даёт чередование 2/3/2/3, а не 2 с потерей половины потока *(по умолчанию 10.0)*
- `Emit End` — Последний кадр, на котором эмиттер испускает частицы. Равный Emit Start = разовый выброс *(по умолчанию 100)*
- `Particle Shape` — Форма столкновений испускаемых частиц. Одна форма на эмиттер
    - **Sphere** — Сфера -- самая дешёвая форма, лучший выбор для больших количеств частиц
    - **Box** — Куб -- дороже сферы, но выглядит как обломки/блоки, а не шарики
    - **Object** — Взять форму и внешний вид у выбранного объекта. Коллизия -- его выпуклая оболочка, поэтому вогнутости заполняются; размер берётся из самого объекта вместе с его масштабом, а Particle Size не используется
- `Particle Object` — Объект, форму и меш которого получают частицы. Берётся его вычисленная геометрия вместе с мировым масштабом, так что частица будет ровно того размера, какого объект выглядит в сцене. Сам объект остаётся в сцене как есть -- пометьте его скрытым, если он нужен только как образец
- `Particle Size` — Радиус (для Sphere) или половина ребра (для Box) испускаемых частиц *(по умолчанию 0.10000000149011612)*
- `Normal Speed` — Начальная скорость частицы вдоль нормали грани, с которой она испущена. 0 -- частица просто появляется и падает под гравитацией *(по умолчанию 0.0)*
- `Inherit Velocity` — Сколько скорости движущегося эмиттера наследуют частицы. 1.0 -- частица вылетает вместе с поверхностью, с которой сошла (гравий, высыпанный из едущего ковша, летит вперёд, а не падает отвесно); 0 -- рождается неподвижной. Скорость считается по конкретной точке поверхности, так что вращение эмиттера тоже учитывается. На неподвижном эмиттере не даёт ничего *(по умолчанию 1.0)*
- `Lifetime` — Через сколько кадров частица исчезает. 0 -- живёт до конца бейка. Исчезновение работает во всех режимах вывода: частица перестаёт сталкиваться и пропадает из облака точек тем же способом, каким её убирает триггер Delete *(по умолчанию 0)*
- `Seed` — Зерно генератора случайных чисел. Одно и то же зерно даёт побитово одинаковый бейк -- меняй, чтобы получить другой рисунок разброса частиц *(по умолчанию 0)*
- `Mass` — Масса тела в килограммах. При разметке проставляется по габаритам объекта и выбранной форме столкновений, дальше живёт своей жизнью: смена Collision Shape или размера её сама не пересчитывает -- для этого есть кнопка рядом. Влияет на столкновения и на отклик на силовые поля (ускорение = сила / масса), но не на свободное падение *(по умолчанию 1.0)*
- **Estimate Mass from Size** — Пересчитать массу выделенных тел по их габаритам и форме столкновений (для эмиттеров -- по размеру частицы). Перезаписывает и вручную заданные значения: масса сама по себе никогда не пересчитывается, это единственный способ вернуть её к оценке по размеру
- `Friction` — Коэффициент трения Кулона, обычно в диапазоне [0,1]. При контакте Box3D комбинирует трение обеих участвующих форм, так что трение статичного пола не менее важно, чем у падающего на него тела. Собственное значение Box3D по умолчанию -- 0.6 *(по умолчанию 0.6000000238418579)*
- `Restitution` — Упругость (отскок), обычно в диапазоне [0,1]. 0 -- совсем не отскакивает, 1 -- отскакивает почти без потери энергии. Как и трение, комбинируется из обеих участвующих в контакте форм. Собственное значение Box3D по умолчанию -- 0 *(по умолчанию 0.0)*
- `Rolling Resistance` — Сопротивление качению, обычно в диапазоне [0,1]. Действует только на формы Sphere и Capsule -- у Box и Convex Hull это поле не имеет эффекта (это ограничение задокументировано в самом Box3D, а не баг аддона). Собственное значение Box3D по умолчанию -- 0 *(по умолчанию 0.0)*
- `Linear Damping` — Гасит линейную скорость тела каждый шаг -- это НЕ то же самое, что Contact Hertz/Damping Ratio в настройках мира (те влияют на жёсткость контакта при столкновении, это -- на затухание скорости тела со временем). Значение может быть больше 1, но чем больше, тем сильнее эффект зависит от размера шага симуляции. Только для Active-тел. Собственное значение Box3D по умолчанию -- 0 *(по умолчанию 0.0)*
- `Angular Damping` — Гасит угловую скорость (вращение) тела каждый шаг -- см. также Linear Damping, работает так же, но для вращения. Только для Active-тел. Собственное значение Box3D по умолчанию -- 0 *(по умолчанию 0.0)*
- `Field Weight` — Множитель силы от силовых полей Blender для этого объекта -- аналог Effector Weights в нативной физике. 0 -- объект не реагирует на поля, 1 -- полная сила. У эмиттера задаёт вес его частиц *(по умолчанию 1.0)*
- `Action` — —
    - **Enable Physics** — Включить физику у объектов, попавших в зону: замороженные (Start Frozen) и статичные тела становятся динамическими и начинают падать
    - **Disable Physics** — Выключить физику: тело замирает там, где его застало, и дальше ведёт себя как статичное препятствие
    - **Delete** — Убрать тело из симуляции и спрятать его до конца бейка -- работает во всех режимах Output, включая частицы эмиттеров
    - **Shatter** — Разорвать связи разрушаемого объекта там, где прошла зона: стена рассыпается по месту удара, а не целиком. Действует только на осколки, созданные Box3D Fracture -- обычному телу рвать нечего
    - **Enable Emission** — Пока зона перекрывает эмиттер, он испускает частицы; триггер ушёл -- эмиссия остановилась. Эмиттер, на который нацелен такой триггер, сам по себе не испускает. Включается и выключается с задержкой в один кадр
- `Affect` — —
    - **All Bodies** — Действовать на любое помеченное тело, попавшее в зону
    - **Collection** — Действовать только на объекты из выбранной коллекции
- `Targets` — Коллекция, объекты которой реагируют на этот триггер
- `Affect Particles` — Действовать и на частицы эмиттеров, а не только на обычные тела *(по умолчанию True)*
- `Once Per Body` — Применить действие к каждому телу только один раз. Выключено -- действие применяется каждый раз, когда тело заново входит в зону *(по умолчанию True)*
- `Shape` — —
    - **Box** — Форма-параллелепипед. Дешевле всего, хороший вариант по умолчанию для блочных объектов
    - **Sphere** — Форма-сфера. Самая дешёвая форма из всех, лучше всего для шаров/обломков
    - **Capsule** — Вертикальная капсула. Хороша для персонажей и предметов, катящихся на ребре
    - **Convex Hull** — Точная выпуклая оболочка геометрии меша. Самая точная, самая дорогая -- используй для неправильных форм, где приближение боксом/сферой выглядит неверно
    - **Mesh** — Точная вогнутая форма по треугольникам меша -- миска, труба, ландшафт. ТОЛЬКО для неподвижных Passive-объектов: Box3D создаёт контакты для меш-формы лишь на статичных телах. Для движущегося вогнутого объекта (ковш на анимации, падающая чаша) бери Compound
    - **Compound** — Собирает форму из дочерних объектов: каждый непомеченный ребёнок даёт свою выпуклую часть (его собственная настройка Shape), и все вместе они образуют одно тело. Единственный способ получить вогнутую форму на движущемся теле -- работает и на Active, и на кинематике
- `Collision Collections` — Каналы столкновений. Два тела сталкиваются, только если у них есть хотя бы один общий включённый канал -- ровно как Collections у нативного Rigid Body. Триггер по этим же каналам решает, кого он вообще способен увидеть. Фильтр работает внутри broad-phase, то есть пара, которая не может столкнуться, даже не проверяется -- это и разделение сцены, и оптимизация одновременно *(по умолчанию False)*
- `Mode` — —
    - **Attract** — Тянуть тела, попавшие в объём, к центру инструмента постоянной силой. Объём и есть форма всасывания: вытяните конус -- получится насадка пылесоса. Тела остаются полностью физическими, их можно перехватить или сбить по дороге
    - **Push** — Толкать тела, попавшие в объём, постоянной силой в заданном направлении -- ветер, который дует только внутри объекта, хоть прямоугольного. Направление -- ось объекта: поверните объект, и повернётся поток. Вне объёма сила не действует
    - **Grab & Carry** — Захватить тела в объёме и перенести к объекту-цели. Пойманное едет как кинематическое тело: оно расталкивает всё, во что упирается по дороге, но само с курса не сбивается -- так это и выглядит, когда предмет переносят рукой. По прибытии -- отпустить, заморозить или убрать
    - **Impulse** — Разовый радиальный импульс на заданном кадре: положительная сила -- взрыв, отрицательная -- схлопывание внутрь. В отличие от двух режимов выше работает не по объёму, а по радиусу, и бьёт по всем динамическим телам из своих каналов столкновений
- `Impulse` — Импульс на квадратный метр площади тела, обращённой к центру (режим Impulse). От МАССЫ не зависит: кубик 0.4 м подставляет примерно 0.16 м², так что при 200 он получает около 32 Н*с -- 32 м/с на массе 1 кг и 1.6 м/с на массе 20 кг. Тяжёлому телу нужно во столько же раз больше. Отрицательное значение схлопывает вместо того чтобы разбрасывать *(по умолчанию 200.0)*
- `Radius` — Радиус импульса в метрах (режим Impulse). Объём-сенсор здесь не участвует *(по умолчанию 3.0)*
- `Falloff` — Расстояние за пределами радиуса, на котором импульс сходит к нулю. 0 -- резкая граница: тело внутри радиуса получает всё, тело в сантиметре снаружи -- ничего *(по умолчанию 1.0)*
- `Frame` — Кадр, на котором срабатывает импульс. Срабатывает один раз за бейк *(по умолчанию 1)*
- `Strength` — Attract -- сила в ньютонах, с которой тело тянется к центру (тяжёлое тело ускоряется медленнее лёгкого, как и в силовых полях). Push -- сила в ньютонах вдоль Direction. Impulse -- импульс на единицу площади, обращённой к центру; отрицательное значение схлопывает вместо того чтобы разбрасывать *(по умолчанию 10.0)*
- `Direction` — Куда толкает Push, в осях объекта-инструмента
    - **X** — Вдоль локальной оси X
    - **-X** — Против локальной оси X
    - **Y** — Вдоль локальной оси Y
    - **-Y** — Против локальной оси Y
    - **Z** — Вдоль локальной оси Z
    - **-Z** — Против локальной оси Z
- `Target` — Куда нести пойманное (режим Grab & Carry). Обычно Empty; может быть анимирован ключами -- цель читается на каждом кадре, так что точка назначения может ехать
- `Scatter` — Разброс точки назначения, в метрах по каждой оси. Каждое тело получает свою случайную поправку от -1 до 1, умноженную на эти числа, так что предметы прилетают в область, а не в одну точку. Ось со значением 0 просто выключена: например X и Y по 0.5, а Z в нуле -- разброс блином, без этажей. Отсчитывается в пространстве цели, так что на бегущем персонаже область едет вместе с ним *(по умолчанию 0.0)*
- `Scatter Seed` — Зерно разброса. Одно и то же значение даёт ту же расстановку при каждом бейке; меняйте, чтобы получить другую *(по умолчанию 0)*
- `Hold` — Сколько кадров держать пойманное на месте, прежде чем начать перенос. Тело всё это время едет вместе с инструментом, так что это и есть таймер "схватил, подержал, понёс" *(по умолчанию 0)*
- `Hold Random` — Разброс задержки, в кадрах: каждое тело держится Hold плюс случайная величина от нуля до этого числа. Без разброса пачка, пойманная в один кадр, стартует разом и прилетает лесенкой -- одинаковые предметы через одинаковые промежутки. Разыгрывается один раз при захвате, из того же зерна, что и Scatter *(по умолчанию 0.0)*
- `Travel` — За сколько кадров пойманное тело доезжает до цели *(по умолчанию 20)*
- `Arc Height` — На сколько метров груз поднимается над прямой линией в середине перелёта. 0 -- летит по прямой. Дуга строится по мировой Z и обнуляется на обоих концах, так что точки вылета и прибытия не смещаются *(по умолчанию 0.0)*
- `Ghost in Flight` — Выключить столкновения у пойманного тела на время перелёта: оно проходит сквозь всё и ничего по дороге не расталкивает. Столкновения возвращаются в момент прибытия. Пока тело "призрак", его не видят и сенсоры, то есть триггеры по дороге на нём не срабатывают *(по умолчанию False)*
- `On Arrival` — —
    - **Release** — Вернуть телу физику в точке назначения: оно падает и катится дальше само
    - **Freeze** — Оставить тело стоять в точке назначения: дальше оно ведёт себя как статичное препятствие и никуда не падает
    - **Delete** — Убрать тело из симуляции по прибытии -- ресурс "засосало" и он исчез
    - **Attach** — Оставить тело на цели: оно продолжает ехать за ней до конца бейка. Это и есть "собрать ресурс в стопку за спину героя" -- Freeze оставил бы стопку висеть там, где герой был в момент прибытия
- `Keep Momentum` — Какую долю скорости прибытия тело оставляет себе, когда On Arrival = Release. 0 -- остановить полностью: груз ставится на место, а не бросается. 1 -- прежнее поведение, тело улетает дальше со скоростью перелёта. Скорость эта от массы не зависит, поэтому короткий Travel разгоняет что угодно одинаково сильно *(по умолчанию 0.0)*
- `Stack Step` — Смещение между соседними доставленными телами, в пространстве цели: первое летит в саму цель, n-е -- в цель плюс это смещение, умноженное на n. Нули -- все в одну точку. Имеет смысл при On Arrival = Attach или Freeze *(по умолчанию 0.0)*
- `Stack Columns` — Сколько тел в ряду, прежде чем начнётся следующий. 0 -- одна линия. При ненулевом значении X и Y смещения раскладывают ряд, а Z поднимает следующий этаж *(по умолчанию 0)*
- `Capacity` — Сколько тел инструмент может нести одновременно (в полёте). 0 -- без ограничения. Слот освобождается, когда тело доехало *(по умолчанию 0)*
- `Double-Sided` — Столкновения с меш-формой с обеих сторон каждой грани. У Box3D меш-столкновение односторонее: тело сталкивается только с той стороной треугольника, куда смотрит его нормаль, а с изнанки проходит насквозь. Включено -- нормали не важны (цена: вдвое больше треугольников в форме). Выключай, если меш замкнутый, с правильными нормалями, и важна память/скорость. Только для формы Mesh *(по умолчанию True)*
- `Max Triangles` — Потолок треугольников в форме столкновений для Mesh/Compound/Convex Hull. Если после склейки вершин и растворения копланарных граней треугольников всё ещё больше, меш автоматически прореживается модификатором Decimate (только для физики -- видимая геометрия не меняется). 0 -- без ограничения, брать меш как есть *(по умолчанию 5000)*
- `Planar Angle` — Порог угла для растворения копланарных граней перед построением формы столкновений. Убирает лишнюю тесселяцию с плоских участков почти бесплатно и без потери формы. 0 -- не растворять *(по умолчанию 0.0872664600610733)*
- `Weld Distance` — Слить вершины ближе этого расстояния перед построением формы столкновений. Чинит разорванные/дублированные вершины, из-за которых форма получается негерметичной. 0 -- не сливать *(по умолчанию 9.999999747378752e-05)*
- `Conveyor Speed` — Скорость ленты: тела, лежащие на объекте, едут вдоль него с этой скоростью за счёт трения, как по конвейеру. 0 -- обычная поверхность. Только для Passive *(по умолчанию 0.0)*
- `Direction` — Направление ленты в осях объекта: поверните объект -- повернётся и лента
    - **X** — Вдоль локальной оси X объекта
    - **-X** — Против локальной оси X объекта
    - **Y** — Вдоль локальной оси Y объекта
    - **-Y** — Против локальной оси Y объекта
- `Start Frozen` — Тело стоит неподвижно (как статичное), пока его не разбудит триггер с действием Enable Physics. До этого гравитация и столкновения на него не действуют, но объект остаётся Active и пишется в кеш как обычно. Это и есть "куча камней, которая оживает, когда по ней проводят ковшом" *(по умолчанию False)*
- `Fast-Moving (CCD)` — Дать этому телу режим непрерывного обнаружения столкновений (CCD) от Box3D. Box3D и так уже свипает любое динамическое тело, двигающееся за один шаг больше своего размера с запасом, так что это в основном помогает мелким/тонким быстрым объектам, проскакивающим сквозь эту эвристику. Стоит дополнительного времени солвера -- включай только для объектов, которые реально проваливаются *(по умолчанию False)*
- `Gravity Scale` — Множитель гравитации для этого тела. 1 -- как у всей сцены, 0 -- невесомость, отрицательное -- всплывает. Пух, воздушные шары, замедленное падение. Действует только на динамические тела *(по умолчанию 1.0)*

- `Y` — — *(по умолчанию False)*

- `Y` — — *(по умолчанию False)*

    - **When Settled** — Начать, когда тело уснуло -- то есть само перестало двигаться. Монетки рассыпались, улеглись и встали
    - **From Frame** — Начать с заданного кадра, дождалось оно покоя или нет

    - **X** — Локальная X
    - **Y** — Локальная Y

- `Rise Frames` — За сколько кадров тело встаёт на ребро. Мгновенный подъём читается как сбой, поэтому по умолчанию не ноль *(по умолчанию 8)*
- `Height Offset` — Поправка к автоматическому подъёму. Высота вставания считается из габаритов объекта, это добавка к ней *(по умолчанию 0.0)*
- `Vary Phase` — Разводить стартовый угол между телами, чтобы куча не крутилась синхронно. Разброс детерминированный: два бейка одной сцены совпадают *(по умолчанию True)*

#### Box3D Fracture · фрагменты и разрушения

*Где:* Properties → physics · свёрнута по умолчанию

Генерация фрагментов меша и настройка связей для разрушения объекта в физической симуляции.

- `Unbreakable` — Связи не рвутся ни при какой нагрузке, что бы ни стояло в Strength. Без этой галочки Strength 0 означает НУЛЕВУЮ прочность, то есть объект разваливается от любого касания -- это важно, когда Strength анимируется ключами: доводя её до нуля, вы разрушаете объект, а не делаете его несокрушимым *(по умолчанию False)*
- `strength` — несколько полей с этим именем в аддоне: Strength
- **Select Source** — Сделать активным исходный объект, из которого нарезаны эти осколки
- **Clear Fragments** — Удалить осколки этого объекта и вернуть оригинал
- `Cells` — Сколько осколков сгенерировать. Зёрна раскидываются равномерно по габаритному ящику объекта, поэтому у вогнутого источника часть зёрен попадает мимо меша и такие ячейки выбрасываются -- это верхняя граница, а не точное число *(по умолчанию 20)*
- `Seed` — Зерно генератора случайных чисел. Одно и то же значение даёт ровно те же осколки *(по умолчанию 0)*
- `linear_hertz` — несколько полей с этим именем в аддоне: Linear Stiffness (Hz)
- `angular_hertz` — несколько полей с этим именем в аддоне: Angular Stiffness (Hz)
- `linear_damping_ratio` — несколько полей с этим именем в аддоне: Linear Damping
- `angular_damping_ratio` — несколько полей с этим именем в аддоне: Angular Damping
- `Fragment Mass` — Задать массу каждому осколку напрямую вместо доли от массы источника. Без этого масса источника делится между осколками по объёму, и мелкие куски получаются очень лёгкими *(по умолчанию False)*
- `Mass` — Масса одного осколка, кг. Одинаковая у всех, независимо от размера. Меньше 0.01 кг не бывает: слишком лёгкое тело отлетает от первого же касания и выглядит как взрыв *(по умолчанию 1.0)*
- `Inner Material` — Материал для граней разлома. Без него скол рендерится наружным материалом, растянутым по срезу. Задаётся до генерации: слот дописывается в осколки, а гранях разлома заодно раскладывается плоская UV-развёртка по плоскости разреза
- **Generate Fragments** — Разбить выбранный меш на выпуклые осколки Вороного и записать граф связей между ними. Оригинал прячется, но остаётся в файле

#### Box3D Joint · соединения тел

*Где:* Properties → physics · свёрнута по умолчанию

Связь двух физических тел: тип соединения, пределы движения, моторы и параметры разрушения связи.

- `Type` — Какие степени свободы соединение оставляет телам
    - **Hinge** — Шарнир: тела вращаются друг относительно друга вокруг ОДНОЙ оси и не могут разъехаться. Дверь на петлях, маятник, звено цепи, локоть куклы. Ось вращения -- локальная Z самого Empty, так что ось задаётся его поворотом
    - **Ball** — Шаровой шарнир: свободное вращение во все стороны вокруг одной точки, без смещения. Плечевой сустав, подвес, шар в гнезде. Конус ограничения центрирован на локальной Z Empty
    - **Distance** — Держит две точки на заданном расстоянии друг от друга: верёвка, трос, подвес, цепь. В отличие от шарнира не ограничивает повороты вообще -- только дистанцию. Пружина делает связь тянущейся, пределы задают минимум и максимум, мотор подтягивает или отталкивает тела вдоль линии между ними
    - **Fixed** — Жёсткая сварка: два тела ведут себя как одно целое, оставаясь раздельными объектами. Ненулевые Hertz делают соединение пружинящим, а не абсолютно жёстким. Box3D предупреждает, что его солвер приблизительный и не удержит жёстко длинную цепочку тел
- `Object A` — Первое из соединяемых тел. Должно быть помечено для Box3D
- `Object B` — Второе из соединяемых тел. Должно быть помечено для Box3D
- `Connected Bodies Collide` — Разрешить соединённым телам сталкиваться друг с другом. По умолчанию выключено: части одного механизма обычно пересекаются геометрически, и контакты между ними только мешают солверу *(по умолчанию False)*
- `Breakable` — Разорвать соединение, когда нагрузка на него превысит порог. Так делаются верёвки, цепи, вывески и вообще всё, что должно оборваться в кадре, а не держать до конца *(по умолчанию False)*
- `Break Force` — Сила в ньютонах, выше которой соединение рвётся. Ориентир: тело массой m под гравитацией висит с силой примерно m*10, так что цепь, держащая 5 кг, живёт примерно до 50 Н *(по умолчанию 500.0)*
- `Break Torque` — Момент в ньютон-метрах, выше которого соединение рвётся. Отдельный порог: вывеску чаще срывает раскачиванием, а не весом *(по умолчанию 500.0)*
- `Limit Angle` — Ограничить угол поворота. Без этого дверь провернётся на полный оборот *(по умолчанию False)*
- `Lower` — Нижний предел угла. Box3D ограничивает диапазон значением -0.99*pi *(по умолчанию -0.7853981852531433)*
- `Upper` — Верхний предел угла. Box3D ограничивает диапазон значением 0.99*pi *(по умолчанию 0.7853981852531433)*
- `Motor` — Активно вращать соединение, а не просто ограничивать его. Мотор борется с гравитацией и контактами в пределах своего максимального момента *(по умолчанию False)*
- `Speed` — Желаемая угловая скорость мотора, радиан в секунду *(по умолчанию 1.5707963705062866)*
- `Max Torque` — Предел момента мотора, ньютон-метры. Слишком маленький -- мотор не сдвинет нагрузку; слишком большой -- продавит сквозь препятствия *(по умолчанию 10.0)*
- `Limit Cone` — Ограничить отклонение от оси Z конусом с заданным углом *(по умолчанию False)*
- `Cone` — Половинный угол конуса ограничения, от 0 до pi *(по умолчанию 0.7853981852531433)*
- `Limit Twist` — Ограничить закручивание вокруг оси Z *(по умолчанию False)*
- `Twist Lower` — — *(по умолчанию -0.7853981852531433)*
- `Twist Upper` — — *(по умолчанию 0.7853981852531433)*
- `Length` — Расстояние, которое джойнт держит между двумя точками крепления. Кнопка From Objects ставит сюда текущее расстояние между объектами -- верёвка с неверной длиной дёргает сцену на первом же кадре, а на глаз это не подобрать *(по умолчанию 1.0)*
- **From Objects** — Поставить Length равным текущему расстоянию между Object A и Object B. Верёвка с неверной длиной дёргает сцену на первом же кадре
- `Spring` — Добавить пружину, возвращающую соединение в исходное положение. Без неё шарнир свободно болтается в пределах лимитов *(по умолчанию False)*
- `Stiffness (Hz)` — Жёсткость пружины в герцах -- сколько колебаний в секунду она делает *(по умолчанию 4.0)*
- `Damping` — Затухание пружины, безразмерное. 1.0 -- критическое, без перелёта *(по умолчанию 0.5)*
- `Max Tension` — Сколько ньютонов растяжения пружина выдерживает. По умолчанию не ограничено *(по умолчанию -3.4028234663852886e+38)*
- `Max Compression` — Сколько ньютонов сжатия пружина выдерживает. По умолчанию не ограничено *(по умолчанию 3.4028234663852886e+38)*
- `Limit Length` — Разрешить длине меняться в пределах от Min до Max вместо жёсткой фиксации. Работает только вместе с пружиной: без неё связь жёсткая и пределы не нужны *(по умолчанию False)*
- `Min Length` — Ближе этого тела не сойдутся *(по умолчанию 0.5)*
- `Max Length` — Дальше этого тела не разойдутся -- это и есть длина верёвки *(по умолчанию 2.0)*
- `Motor Speed` — Скорость мотора вдоль линии между телами, МЕТРОВ в секунду -- в отличие от мотора шарнира, который задаётся в радианах в секунду. Положительная растягивает, отрицательная стягивает: лебёдка *(по умолчанию 0.0)*
- `Max Motor Force` — Предел силы мотора в НЬЮТОНАХ -- у шарнира то же поле в ньютон-метрах, величины несопоставимы *(по умолчанию 100.0)*
- `linear_hertz` — несколько полей с этим именем в аддоне: Linear Stiffness (Hz)
- `angular_hertz` — несколько полей с этим именем в аддоне: Angular Stiffness (Hz)
- `linear_damping_ratio` — несколько полей с этим именем в аддоне: Linear Damping
- `angular_damping_ratio` — несколько полей с этим именем в аддоне: Angular Damping
- **Remove Joint** — Убрать соединение Box3D с выбранных Empty
- **Mark Joint** — Сделать выбранные Empty соединениями Box3D. Empty задаёт точку и оси соединения: шарнир вращается вокруг его локальной Z

#### Zhb Zondbe · роли объекта и зоны

*Где:* Properties → physics · свёрнута по умолчанию

Назначение роли выбранному объекту в симуляции толпы и настройка земли, препятствий, зон, точек появления и ворот.

- **Mark Ground** — Сделать выделенное землёй: по её габаритам строится сетка
- **Mark Obstacle** — Сделать выделенное препятствием
- **Mark Zone** — Сделать выделенное зоной-целью
- **Mark Spawn** — Сделать выделенное спавнером
- **Mark Gate** — Сделать выделенное воротами: прошедшая толпа меняет численность
- **Unmark** — Убрать роль: симуляция перестанет видеть эти объекты
- `Role` — Чем этот объект работает в симуляции толпы
    - **None** — Обычный объект, симуляция его не видит
    - **Ground** — Плоский меш, по габаритам которого строится сетка. Должен быть ровно один: всё за его пределами непроходимо
    - **Obstacle** — Непроходимо. Растеризуется по поверхности, так что внутренность закрытой коробки остаётся проходимой, но запертой
    - **Zone** — Цель. Радиус равен видимому размеру пустышки. Стрелка вместо сферы означает направление, а не место
    - **Spawn** — Откуда появляются агенты. Пустышка даёт диск, любой другой объект — эмиттер по его рёбрам
    - **Gate** — Ворота: агент, прошедший через них, меняет численность толпы — умножает, добавляет или убавляет. Радиус равен видимому размеру пустышки, как у зоны. Каждое тело проходит одни ворота один раз
- `Gate` — Что ворота делают с толпой
    - **Multiply** — Каждый прошедший приводит с собой ещё (N-1) таких же. ×2 — толпа удваивается по мере прохода
    - **Add** — Один раз выпускает N новых рядом с первым прошедшим
    - **Subtract** — Забирает первых N прошедших: они исчезают из кадра
- `Value` — Множитель для «Multiply», число агентов для «Add» и «Subtract» *(по умолчанию 2.0)*
- **Copy To Selected** — Скопировать настройки активного объекта на остальные выделенные с той
же ролью
- `Agents` — Сколько агентов выпускает именно этот спавнер. Спавнеров может быть сколько угодно, и в кадре окажется их сумма *(по умолчанию 200)*
- `Release Over` — За сколько кадров этот спавнер выпустит всех своих. Ноль — все появляются сразу в первом кадре. Число агентов при этом не меняется: ещё не выпущенные помечены alive=0, и их отсекают геоноды *(по умолчанию 0)*
- `Spawn Spread` — Случайный сдвиг стартовой позиции. Нужен линейному эмиттеру: без него получается идеально ровная шеренга *(по умолчанию 0.0)*
- `Team` — Сторона, за которую играют агенты этого спавнера. Агенты разных сторон бьют друг друга, если включён бой. Номер доезжает до точечного облака атрибутом agent_team — по нему геоноды и красят команды по-разному *(по умолчанию 0)*
- `Hit Points` — Сколько попаданий держит агент этого спавнера, прежде чем исчезнет. Работает только при включённом бое *(по умолчанию 3)*
- `Order` — Место зоны в маршруте. В режиме «По порядку» толпа идёт по возрастанию этого числа, при равенстве — по имени. В режиме «Случайно» число ни на что не влияет, кроме порядка в списке *(по умолчанию 0)*
- `Remove On Arrival` — Дошёл до этой зоны — и выбыл из симуляции: помечается alive=0, перестаёт двигаться, толкаться и что-либо стоить солверу. Для последней зоны маршрута это чистая экономия: толпа, которая ушла за кадр и стоит там до конца ролика, считается полностью, хотя её никто не видит. Геоноды отсекают такого агента ровно так же, как ещё не выпущенного *(по умолчанию False)*
- `Queue` — Обслуживать по одному, остальных держать в порядке подхода. Без этого зона — просто место, куда все приходят и стоят кто где успел *(по умолчанию False)*
- `Queue Shape` — Лента или толпа. Обслуживание по одному в обоих случаях
    - **Line** — Стоят друг за другом: по нарисованной кривой или прямой от зоны. Первым обслуживают того, кто дольше всех стоит
    - **Fan** — Осаждают зону сектором: кольца мест вокруг точки обслуживания, внутренние заполняются первыми. Первым обслуживают того, кто ближе всех — в толпе никто не помнит, кто за кем занимал, и честная очередь читалась бы как лента странной формы
- `Spread` — Ширина сектора, в котором стоит толпа. 180° — осаждают спереди по всей полуплоскости, 360° — со всех сторон (тогда направление пустышки не нужно) *(по умолчанию 3.1415927410125732)*
- `Queue Line` — Кривая или меш-линия, вдоль которой стоит хвост. Нужна, если очередь заворачивает за угол или идёт змейкой. Без неё хвост тянется прямой по локальной +Z самой зоны — поверните пустышку набок, стрелкой её видно
- `Queue Step` — Расстояние между стоящими. Меньше радиуса расталкивания можно для плотной очереди: заняв место, агент стоит на нём и не расталкивается. Слишком малый шаг даст видимое пересечение персонажей *(по умолчанию 0.800000011920929)*
- `Unlimited Places` — Лента держит всех, кто есть в сцене: мест ровно столько, сколько агентов у спавнеров. По направлению хвост просто становится нужной длины, по кривой — заканчивается вместе с кривой, и не поместившиеся ждут рядом *(по умолчанию False)*
- `Queue Places` — Сколько человек помещается в ленту. Пришедшие сверх этого ждут рядом и встают, как только место освободится *(по умолчанию 20)*
- `Service Trigger` — Объект, который отпускает обслуженного: как только он оказывается в своём радиусе от точки обслуживания, передний уходит и очередь сдвигается. Заключуйте его анимацией — так момент задаётся с точностью до кадра. Пусто — обслуживание длится время стоянки этой зоны
- `Custom Idle Time` — Задать этой зоне собственное время стоянки вместо общего. Взгляд в витрину — две секунды, очередь у двери — пятнадцать, и одно число на всех делает все остановки одинаковыми на вид *(по умолчанию False)*
- `idle_min` — несколько полей с этим именем в аддоне: Idle From, Stay From
- `idle_max` — несколько полей с этим именем в аддоне: Idle To, Stay To
- `Custom Arrival Spread` — Задать этой зоне собственный разброс дистанции остановки вместо общего *(по умолчанию False)*
- `arrive_min` — несколько полей с этим именем в аддоне: Arrive From, Stop Short From
- `arrive_max` — несколько полей с этим именем в аддоне: Arrive To, Stop Short To

## 7. Когда что-то идёт не так

**Аддон не включается.** Сначала проверьте наличие `zhb_core` ≥ 0.8.0 и путь его импорта. Сообщение в консоли
говорит это прямо. Библиотека ставится как обычный аддон, но
**галочку ей ставить не нужно**.

**Инструмента нет в списке.** Выбор вверху Anim/Studio показывает только
включённые пакеты. Выделение другого объекта само инструмент не переключает.

**После добавления цели остался старый отчёт.** У толпы повторите
«Проверить роли сцены»; отчёт до изменения состава целей уже не актуален.

**Вкладки нет в сайдбаре.** Аддон не включён, либо включён, но упал при
регистрации — смотрите системную консоль Blender.

**Кнопка «Создать стопку» серая.** Не выбран источник: объект или непустая
коллекция.

**Толпа стоит на месте.** Между спавном и зоной стена: поле течения упирается в
неё, агенты читают нулевой вектор. Бейк об этом скажет и откажется, если только
вы не переключили «Если прохода нет» на «Упираться в стену». Проверьте также,
что объект с ролью Ground ровно один и спавнеры стоят на нём.

**Толпа перестала расти на воротах.** Кончился резерв. Поднимите
**Gate Reserve Cap** или уменьшите множители — точное число бейк называет.

**В бою все умирают в первый же кадр касания.** Слишком маленькая пауза между
попаданиями (**Hit Every**, в кадрах).

**Тело проваливается сквозь пол.** Меш-форма стоит на движущемся теле: Box3D
создаёт меш-контакты только на статичных. Возьмите Compound.



**Предметы не летят в корзины.** В режиме By Kind у предмета и корзины должны
совпадать значения свойства вида. Кого не разложило — сказано в отчёте
оператора.

**Рендер выглядит мылом.** Активны прокси-текстуры. Верните оригиналы в
**Прокси текстур**.

**Delivery не принимает кадры.** Проверьте диапазон исходного `.blend`,
первый номер, формат и размеры. Неполная или повреждённая последовательность отклоняется.

**Профиль разошёлся с исходниками.** `bash zhb_core/tools/install_all.sh --check`
скажет, какие пакеты отличаются, ничего не меняя.

## 8. Чего аддоны намеренно не делают

- **Не ходят в сеть.** Ни один. Обновление — переустановка архива или `git pull`
  плюс установщик.
- **Не считают физику и толпу во время рендера.** Только читают готовый кэш.
- **Не лезут друг к другу.** Общие данные передаются файлами и свойствами сцены,
  а не вызовами.
- **Не переименовывают свойства сохранённых сцен** без миграции: под старыми
  именами лежат данные в уже сохранённых `.blend`.
- **Не угадывают там, где нет правильного ответа** — отказываются и показывают,
  что именно непонятно.

## 9. Проверка дочернего Blender

Frame Analysis и Delivery передают дочернему процессу манифест с отпечатками
исполняемых файлов, ресурсов и библиотек платформы. Изменённый код или другой
Blender отклоняется до оценки сцены. Документация и тесты в отпечаток не входят.
Общие проверки находятся в Core; кэши толпы, частиц и физики проверяют собственные
провайдеры. Сохранённый READY без действующей проверки не считается подтверждением.

Delivery может читать старый журнал Render Supervisor под отдельной галочкой.
Это совместимость чтения; создание и запуск очереди удалены.
